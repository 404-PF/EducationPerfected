# Phase 3 release evidence

No release workflow currently exists. `npm run build:linux-dev` and `npm run build:windows-dev` are local development builds, not releases. The Windows experiment has no final valid signing or distribution policy. `npm run release:check` is a fail-closed evidence checklist, not an upload command or permission to publish.

Create an untracked `release/evidence.json` from the example only after evidence is reviewed. Every global and per-target check must be `passed`, name the exact current source commit, link its evidence and name its reviewer. A skipped Windows child-signal fixture, another platform's result or package availability is not native proof. The validator checks completeness and freshness, not evidence authenticity or legal clearance. A future release workflow must invoke this check before any artifact publication, and still require owner authority.

Native lanes selected by the owner: Windows x64, macOS ARM64, macOS x64, Linux x64, Linux ARM64. Current development builders support native glibc Linux x64/ARM64 and Windows x64. macOS builders remain unfinished. Windows native credential CRUD and real console/no-Node checks remain unproved. All lanes still need complete release evidence, including signing-compatible payload verification and native hosts. For each lane verify: no-Node fresh machine launch, extracted browser path, native credential save/read/delete, safe console shutdown, packaging integrity and the selected signing/unsigned policy. Windows needs actual console events, not child.kill emulation. No paid runners or certificates are approved by this checklist.

Global gates: project contribution rights, browser redistribution, dependency notice completeness and artifact integrity. Source licenses recovered from exact npm gitHead are recorded under `packaging/notices/provenance.json`; copying license texts does not settle all legal obligations or project rights. Browser files and native binary third-party notices also need review.

The checkout must be clean, including source hidden by local/global Git excludes. Only generated `node_modules/`, `build/` and `release/evidence.json` are allowed as untracked paths. Git environment overrides are removed and Git is invoked only at `/usr/bin/git` (Linux/macOS) or `C:\Program Files\Git\cmd\git.exe` (Windows). Nonstandard installations fail closed; this does not certify native Windows/macOS lanes. Evidence references must be HTTPS URLs without URL userinfo or existing files (symlinks are followed) named by an absolute path or `./` path relative to the checkout. Paths may be outside the checkout; HTTPS query strings may contain credentials, so do not put secrets in evidence references. HTTPS reachability, report contents and reviewer identity are still out-of-band checks. The builder must use the same clean commit; the checker cannot prevent source edits after it returns.
